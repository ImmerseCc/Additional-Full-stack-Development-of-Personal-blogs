## 一、项目主指令（首轮下达）

你将作为我的资深全栈开发搭子，和我一起完成《VibeCoding 大实战：个人博客全栈项目》。我通过 Kimi Code 桌面端接入你，当前模型按 DeepSeek v4.1 使用。请严格按下面分条要求协作，不要一次性生成全部代码，必须分阶段推进，每阶段结束等我确认后再继续。

### 一、你的角色与总目标

1. 你负责规划、写代码、改代码、给命令、做审计、整理文档；我负责确认方向、运行验证、最终验收。
2. 目标：交付一个能运行的个人博客全栈项目，前端 + 后端合并为一个完整项目仓库。
3. 必须遵守：不得直接使用任何现成博客模板或整站主题，所有页面、组件和接口必须由你根据我的需求生成或修改实现。
4. 你每次回复必须具体、可落地，不能只给"可以加一个功能"这种建议，必须告诉我改了哪些文件、怎么运行、怎么验证。

### 二、总体技术限制

1. 前端必须使用 JavaScript，可配合 HTML/CSS。
2. 前端框架由你推荐，建议 React / Vue / Svelte 中的一种；样式方案由你推荐并给出理由。
3. 后端只能使用 Java，框架由你根据语言习惯推荐。
4. 数据持久化使用轻量方案，例如 SQLite、文件存储等；不要引入我完全不会启动的大型数据库集群或复杂中间件。
5. 前端和后端最终要能合并为一个完整项目仓库，建议使用 frontend/ 和 backend/ 目录结构，根目录放 README.md。

### 三、前端要求

1. 必须包含 6 个核心功能模块，每个模块至少有一个可感知的交互或视觉亮点。
2. 模块一：全局导航与主题。要求响应式导航栏、移动端汉堡菜单、深色/浅色主题切换、平滑过渡、当前页面高亮。
3. 模块二：文章列表展示。要求卡片式布局、分页或无限滚动、卡片悬停/点击动效、骨架屏或加载动画。
4. 模块三：文章详情页。要求支持 Markdown 渲染或富文本、阅读进度条、图片懒加载、代码块语法高亮。
5. 模块四：搜索与分类过滤。要求实时搜索并做防抖、按标签/分类过滤且可多选、结果为空时友好提示动画。
6. 模块五：评论与互动。要求评论表单、前端校验、错误提示动画、点赞按钮带数字动画和状态保存、Toast 通知自动消失。
7. 模块六：数据持久化与模拟。要求使用 localStorage 或 IndexedDB 保存点赞、评论、主题偏好；刷新页面数据不丢失；提供可重置数据按钮。
8. 前端存在加分项，但不要影响基础功能：CSS 变量主题系统、跟随系统主题、路由过渡动画、文章目录自动生成与滚动监听、IntersectionObserver 滚动动画、图片懒加载、代码分割、虚拟列表、可托管到 GitHub 或服务器。
9. 前端需对接我们自己的后端。

### 四、后端要求

1. 后端必须提供完整 RESTful API 服务，支持文章和评论的增删改查，数据持久化存储。
2. 最低必须完成 6 项功能：查看文章列表且支持分页、查看文章详情、创建文章、修改文章、删除文章、保存数据且重启项目后不丢失。
3. 数据保存方式由你推荐并实现，优先轻量方案，例如 SQLite 或文件存储。
4. 后端加分项尽量做：文章分类或标签管理、标题关键词搜索、文章状态草稿/已发布、统一错误返回格式、评论独立增删改查接口、接口输入校验、Swagger/OpenAPI 文档。
5. 后端代码要有基本分层结构，例如路由层、服务层、数据访问层、模型层，不要全部写在一个文件里。

### 五、前后端协作要求

1. 前端通过 fetch 或 axios 调用后端 API 获取真实文章数据。
2. 评论和点赞数据通过后端接口持久化存储。
3. 前后端统一接口契约，使用 RESTful 风格。请先提出接口契约草案，包括路径、方法、请求参数、返回格式，等我确认后再实现。
4. 建议统一返回格式，例如 { code, message, data }，并统一错误处理。

### 六、VibeCoding 协作与记录要求

1. 你必须保留并协助整理完整的 AI 协作过程，不能只提交最后代码。
